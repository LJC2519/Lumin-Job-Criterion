# LJC 分解模板（可独立使用）

> 把任意任务填进这个骨架。规则详情见 SKILL.md「第 1 步：模块化分解」。
> 来源：to-tickets 的 tracer-bullet + writing-plans 的 right-sizing + HTN 递归展开。

```
L0 总任务：<一句话说清最终产出>

├─ L1 模块 A（能力域：程序/数据/材料/研究/协作/交付）
│   ├─ L2-A1 <小任务>
│   │      产出：<可验收的东西>
│   │      标准：<怎么算做完——可验证，不靠感觉>
│   │      依赖：无 / L2-XX
│   │      可并行：是（与其他 L2 无共享状态）/ 否
│   │      资源：<需要什么——文件/数据/权限/上下文>
│   └─ L2-A2 <小任务>｜…｜依赖：L2-A1
├─ L1 模块 B（能力域：…）
│   └─ L2-B1 …
└─ L1 模块 C（能力域：…）
    └─ L2-C1 …
```

## 填写纪律（不满足就继续拆或合并）

1. 每个 L2 四件套齐全：一句话 / 产出物 / 可验证标准 / 依赖
2. L1 模块 3–5 个；L2 总数 ≤ 9
3. **垂直切片**：每个 L2 切一条「窄而完整」的路径，独立可演示——不要按技术层横切
4. **右尺寸**：拆分点 = 验收者可能拒 A 而批 B 之处；准备工作并入需要它的任务
5. **先易后难**：让后续变简单的重构（prefactor）排最前
6. **宽重构例外**：机械全局变更按 expand–contract 走（加新→分批迁移→删旧）
7. **独立性标注**：无共享状态/顺序依赖的 L2 标「可并行」
8. **资源标注**：资源缺失的 L2 优先级自动靠前
9. **拆不下去分两种**：⟲ 复合任务（执行期递归再拆）/ 黑箱（真缺口，如实标注）

## 分解完成后

1. 按 L2 逐个检索技能（不要按 L0 检索）
2. 标「可并行」的独立任务 ≥2 个 → 考虑并行执行
3. 代码类任务可选：to-spec 固化规格 → to-tickets 拆工单 → implement 实施
4. 零命中的环节如实标缺口——不硬凑
