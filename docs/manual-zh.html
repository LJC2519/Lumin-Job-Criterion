一、LJC 是什么

技能越装越多（100+ 是常态），接任务时却不知道有什么可用。LJC 补这个缺口：接到任务后，它带你走完一条固定流水线——

任务进来 → ① 验料 → ② 拆分（L1→L2→L3 五要素）→ ③ 四路检索（skills + 可借鉴开源项目）
        → ④ 双审查门（安全尺 × 适用尺）→ ⑤ 覆盖图（含依赖连线）→ 盘点建议

最终交付一张「任务 → 技能覆盖图」：每个子任务由谁解决、依赖顺序如何、哪里是缺口——你照图执行即可。

二、快速开始

安装（3 行）：

git clone https://github.com/LJC2519/Lumin-Job-Criterion.git
cd Lumin-Job-Criterion
python3 scripts/find.py build     # 首次自动建索引，<1 秒

触发语句（对话里说）：

「请ljc为我指点迷津」 · 「用 LJC 找技能：<任务>」 · 「让 LJC 路由这个任务：<任务>」

也可以不用对话模式，直接命令行检索（见第八节速查表）。

三、五步流水线

四、拆到多细？—— L3 原子任务五要素

任务拆到「交给任何人都能照着做完、不需再猜」为止。每个原子任务必填五要素：

L3-<父编号>-<序号> <一句话动作>
  输入：     动手前必须具备的东西（文件/数据/上文产物/权限）
  输出：     做完交付的实体（可点开/可运行/可验证）
  前置依赖： 必须先完成的 L3 编号；无则写「无」
  执行顺序： 本父任务内第几步；可并行则标「可并行」
  完成标准： 怎么判定做完（可验证、不靠感觉；附验收命令更佳）

粒度过尺：输入与输出能一口气说清＝粒度合适；说不清＝继续拆；一分钟就能做完＝过碎，与相邻合并。

五、匹配不局限对口—— 宽口径三分类

相关度适配方式含义必填
高（对口）直接使用现成覆盖该子任务，拿来就用解决哪个子任务
中（沾边）改造适配底层能力对口，需改配置/换源/调参/拼接改造要点（改哪、改成什么、成本）
低（思路）思路参考不进产物，实现思路/清单可借鉴借鉴哪一点（仅方法论，不冒充成品）

匹配对象除 skills 外还包括开源项目（普通代码仓库）：必填「匹配理由 + 可借鉴点 + 改造要点」，且必须先过安全尺。

六、双审查门 —— 两把尺都要过

安全尺三档：BLOCK（管道执行远程脚本/编码载荷/提示词注入/凭证泄漏——照常告诉你但标高危）、WARN（缺 license/外部调用/星数低——附警告介绍）、PASS（正常推荐）。适用尺：逐个读 SKILL.md 原文按 0–1 判分，≥0.8 对口 / 0.5–0.7 沾边 / <0.5 不当推荐。

八、命令速查

命令作用
python3 scripts/find.py query "<词>" --top 8本地已装技能检索（秒回，中英文均可，130+ 术语映射）
find.py suggest "<任务>"任务盘点：相关候选 vs 本次用不到（停用需你同意）
find.py build / list / doctor重建索引（<1 秒）/ 列出全部 / 一键自检
find.py rerank "<任务>" ＋ rerank apply … --scores候选精排：脚本出题 → 宿主判分 → 权威回流
find.py semantic向量后端自检（默认关：实测 ROI 为负）
github_search.py "<词>" / --catalog仓库雷达（按星扫） / 四个技能目录全文检索
web_search.py "<词>"全网语义搜索（需 TAVILY_API_KEY，未设自动跳过）
security_check.py <路径或 owner/repo>安全门：BLOCK / WARN / PASS
check_updates.py [技能名]更新检测：git / tarball SHA / 日期三轨
