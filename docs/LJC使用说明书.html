一、LJC 是什么

技能（Skill）越装越多，但「这个任务到底该用哪个技能」没有现成工具能回答。 LJC 就是补这个缺口的：把你说的大任务拆成小任务，找到每个小任务能用的技能， 过一道安全检查，最后画一张「任务 → 技能」覆盖图——哪些部分有现成技能、哪些是缺口，一眼看清。

图 1 · LJC 定位：任务进来，四路检索，出一张覆盖图

它只做两件事

主责含义
分解任务把大任务拆成模块 → 小任务 → 原子任务。每个原子任务写清五要素：输入 / 输出 / 前置依赖 / 执行顺序 / 完成标准——拿到手就能做，不用再猜。
找技能为每个小任务匹配现成技能或可借鉴的开源项目，按相关度分三类：直接使用 / 改造适配 / 思路参考，并附改造要点和匹配理由。
它不做什么（重要预期）：LJC 只给信息、给路径、给命令，不会替你下载、安装、执行任何东西。 零命中的时候它会直说「没有」，不会硬凑一个不相关的推荐糊弄你。

二、下载与安装（3 分钟）

LJC 托管在 GitHub：github.com/LJC2519/Lumin-Job-Criterion。纯 Python 标准库实现，不需要 pip install 任何东西，clone 下来就能跑。

第 1 步 · 克隆仓库

终端
$ git clone https://github.com/LJC2519/Lumin-Job-Criterion.git
# 国内网络慢可用镜像：
$ git clone https://ghproxy.net/https://github.com/LJC2519/Lumin-Job-Criterion.git
$ cd Lumin-Job-Criterion

第 2 步 · 立刻试一条命令（验证装好了）

终端
$ python3 scripts/find.py doctor

LJC doctor —— 自检
 ✓ 索引：115 个技能，建于 2026-10-27 11:10:58（9 分钟前）
 ✓ GitHub 可达（市场通道可用）
 ✓ 技能目录缓存：13 个文件（7 天 TTL）
结论：全部正常

第一次运行会自动扫描技能目录、建立索引（约 1 秒），无需手动初始化。

第 3 步（可选）· 注册成 WorkBuddy 技能

如果你在用 WorkBuddy，把它链进技能目录，之后在对话里说一句话就能调用整个流程：

终端
$ ln -s /path/to/Lumin-Job-Criterion ~/.workbuddy/skills/lumin-job-criterion
$ python3 ~/.workbuddy/skills/lumin-job-criterion/scripts/find.py build
可选增强（不影响基本使用）： ① 设置 GITHUB_TOKEN 环境变量 → GitHub 检索限额从 10 次/分提到 30 次/分； ② 配置 Tavily key 开启「全网语义搜索」通道 → 见 FAQ 第 5 条。

图 2 · 安装只需两步，第三步可选

三、最常用法：在 WorkBuddy 里说一句话

多数时候你不需要碰终端。在 WorkBuddy 对话里说：

WorkBuddy 对话框
请ljc为我指点迷津：我想给团队做一个任务分配看板

LJC 会自动走完全流程：验料（确认任务前提）→ 拆解（L1 模块 → L2 小任务 → L3 原子任务）→ 四路检索 → 安全审查 → 画出带依赖关系的覆盖图。你照图执行即可。

触发说法效果
请ljc为我指点迷津：<任务>完整流程：拆解 + 匹配 + 双审查 + 覆盖图（大小写均可）
用 LJC 找技能：<任务>同上，说法更直白，歧义更小
有没有技能能做X？直接检索模式：本地秒回，查不到自动转 GitHub / 市场搜
这个任务该怎么拆？只要拆解，不检索
触发小坑：「请ljc为我指点迷津」里的「为我」偶尔会被理解成「用户在向助手本人求教」而错过加载。 如果没触发，换「用 LJC 找技能：<任务>」这种说法，100% 能认。

四、命令详解

所有命令都在 scripts/ 目录下，用 python3 运行。下面按使用频率从高到低讲。

4.1 find.py query —— 检索技能（最常用）

在本地已装的技能里按功能搜。中英文都行，支持口语（内置术语映射会把「画个图」扩展成 diagram 等英文词）。

终端 · 真实输出
$ python3 scripts/find.py query "把合同审查一遍" --top 3

查询「把合同审查一遍」→ 扩展检索词 9 个：16 个关键词命中
 检索方式：仅词袋 · 耗时 3ms

 1. [contract-review]  (来源:claude-legal-skill  得分:194)
    Review legal contracts, NDAs, employment agreements...
    命中: name~contract, desc~review, 覆盖3词+60

 2. [contract-review-pro]  (来源:contract-review-pro  得分:123)
    专业合同审核 Skill：7步工作流、5类通用门禁+16个专项门禁…

 3. [light-review-rebuttal]  (得分:103) …
参数说明
--top N显示前 N 条（默认 5）
--json输出 JSON（给程序或工作流用）
输出里的三分区要会看：① 关键词命中（最相关）② 语义候选（可能相关） ③ 「下载了，但没有注册」——作者禁用了自动调用的技能，能看见但当前加载不到，会单独标出来。

4.2 find.py suggest —— 任务盘点

给一个任务描述，它把已装技能分成「相关有用」和「本次用不到」两栏——适合定期清理技能库、 或接任务前先看看手头有什么牌。

终端
$ python3 scripts/find.py suggest "把申报书数据合规章节加工成评委友好版"

4.3 find.py list / stats —— 看库和看命中

list 列出全部已索引技能；stats 看历史上哪些技能被检索命中最多、哪些从来没人用过（清理时的依据）。

终端 · 真实输出
$ python3 scripts/find.py stats

LJC 命中统计 —— 历史 101 条记录
── 命中次数 Top 10 ──
  light-review-rebuttal    54 次
  light-typesetting        52 次
  customs-trade-compliance 40 次 …

4.4 find.py doctor —— 一键体检

出问题先跑它：检查索引新鲜度、断链、目录健康、网络通道、缓存状态，并给出修复建议（比如哪块缓存可以清）。

4.5 github_search.py —— GitHub 检索

本地没有的，去 GitHub 上找。一次查询自动拆成「精准 AND + 宽召回 OR」两组搜索再合并重排，多词长句也不会空手而归。

终端
$ python3 scripts/github_search.py "法律文书 信息抽取"
$ python3 scripts/github_search.py "diagram" --catalog   # 搜技能目录合集
$ python3 scripts/github_search.py "pdf" --mode both --limit 8
未认证的 GitHub 搜索限额是 10 次/分钟，连续搜索可能撞限（会明确报错并告诉你几秒后恢复）。 设置 GITHUB_TOKEN 环境变量可提到 30 次/分。

4.6 web_search.py —— Tavily 全网语义搜索（可选通道）

前三路都搜不到的冷门技能，用 AI 语义搜索引擎在整个互联网（博客、论文、独立开发者仓库）捞。 结果自带相关度评分，中文任务也能捞到英文技能。

终端
$ python3 scripts/web_search.py --check          # 通道自检
$ python3 scripts/web_search.py "pdf to word" --limit 8
需要免费注册 Tavily（app.tavily.com，免费档约 1000 次/月）拿到 key。 配置一条命令搞定，见 FAQ 第 5 条。不配置也不影响其他通道。

4.7 security_check.py —— 安全检查（装技能前必跑）

装任何第三方技能之前，先让它过一遍：扫描脚本里的可执行风险、SKILL.md 里的提示词注入和凭证泄露。

终端 · 真实输出
$ python3 scripts/security_check.py owner/repo

  [WARN ] SKILL.md 缺 description 字段   ← 提醒，人工看一眼
  结论: WARN —— 照常推荐，但附上警告由你定夺
  # 三档结论：BLOCK（别装）/ WARN（可用但留意）/ PASS

4.8 check_updates.py —— 更新检测

一次性核对你装的技能有没有上游新版本（当前覆盖 36 个来源 / 115 个技能），列出哪些可升级。

4.9 进阶：rerank 精排 与 eval 评估集（维护者用）

find.py rerank "任务" 生成候选清单和评分量尺，配合宿主模型逐条判分后用 rerank apply 回流——检索排序的精修手段。 eval/run_eval.py 是 22 条中英口语用例的回归评估（--save 存基线、--compare 对比）， 改了检索逻辑后跑一次，防止检索质量退化。日常使用不需要碰这两个。

以一个真实任务为例：「把 Word 版申报书转成 PDF 发给老师」。看 LJC 怎么走完全程。

图 3 · 五步流水线：触发 → 拆解 → 检索 → 双审查 → 覆盖图（缺口会用红色标出来，不糊弄）

六、常见问题 FAQ

1. 搜不到某个我确定装了的技能？

九成是索引过期（新装的技能还没进索引）。跑一条命令重建：

终端
$ python3 scripts/find.py build

LJC 也有自愈机制（索引和磁盘对不上会自动重建），但手动 build 永远是最稳的兜底。 重建后再用 find.py list | grep 技能名 确认它在不在库里。

2. 用中文搜有结果，但总感觉差一点？

技巧三则：① 用功能描述词（「合同审查」「流程图」「记忆管理」），别用技能名； ② query 是本地词袋检索 + 术语映射，冷门领域词可以自己加进 scripts/ljc_terms.json （参考同目录 .example.json 的格式，如 "拆包": ["unpack", "asar"]）； ③ 本地搜不到就换通道：github_search.py、SkillHub、Tavily 一路往外扩。

3. GitHub 搜索报「限额」错误？

未认证搜索限额 10 次/分钟，等一分钟自动恢复。要长期高频用：GitHub → Settings → Developer settings → Personal access tokens 生成一个 token（无需任何权限勾选），然后 export GITHUB_TOKEN=ghp_xxx （建议写进 ~/.zshrc），限额提升到 30 次/分。

4. WorkBuddy 市场里明明有某技能，为什么安装总失败？

实测规律（2026-10-27 验证）：每装一个技能，安装前必须紧跟一次「包含该技能名的搜索」—— 跟踪按名字记，隔了几轮对话就失效；另外单条安装必成功，两条合并装会被拒。 搜索时用描述性关键词（如「记忆管家」「省token」），直接搜技能名反而返回空。

5. 怎么开启 Tavily 全网语义搜索？

① 到 app.tavily.com 免费注册（约 1000 次/月），Dashboard 复制 API Key；② 运行一键脚本：

终端
$ bash scripts/setup_tavily.sh <粘贴你的 tvly-... key>
# key 不想经过终端历史的话：先复制 key，再跑
$ bash scripts/setup_tavily.sh --clipboard

脚本会写入 ~/.zshrc + 本地密钥文件（WorkBuddy 这类 GUI 应用读不到 .zshrc，文件通道才真正生效）、 自检并实跑一次证明打通。跑完用 web_search.py --check 随时确认。

安全提醒：key 等同门锁钥匙，不要发到群里/贴进聊天记录；万一贴了，去 Dashboard 删掉重建一把即可（轮换比删除记录更彻底）。

6. 「语义后端未启用」的提示是什么意思？要开吗？

不用开。内置的词袋检索（关键词 + 术语映射 + TF-IDF）已经覆盖绝大多数场景且毫秒级响应； 向量语义后端实测收益为负（22 条评估用例只多对了 1 条，却要 20 秒加载模型），所以默认关闭。 真想试：pip install sentence-transformers 后 export LJC_SEMANTIC=auto， 用 find.py semantic 自检，不想要了 semantic --clear-cache 一键清掉。

7. 索引文件 index.json 要不要提交到 git？

不用，它在 .gitignore 里。任何人 clone 后第一次运行 query 会自动建索引（约 1 秒），零配置。

七、注意事项与安全约定

约定内容
只读不装LJC 默认只检索、只推荐，不自动下载安装任何技能。装不装永远由你拍板。
安全红线安全检查结论为 BLOCK 的候选不推荐；WARN 的会附上警告由你定夺。装任何第三方技能前先跑 security_check.py。
不硬凑零命中时 LJC 会直说「没有，最接近的是 X 但它其实做的是 Y」。把不确定说成确定，比没有答案更糟。
未注册 ≠ 没装输出里「下载了，但没有注册」分区的技能：文件在磁盘上，但作者禁用了自动调用，当前会话加载不到。要用需手动处理。
成本纪律本地检索毫秒级零成本；GitHub 通道注意限额；Tavily 有月度免费额度。简单任务（改错别字、查事实）不必走 LJC 完整流程——路由本身有成本。
密钥安全Tavily key / GitHub token 只放环境变量或本地密钥文件，永远不要发进群聊、聊天记录或提交到 git。
